## Description (설명)
**Libftprintf** 본 프로젝트의 목표는 C 표준 라이브러리의 printf 함수를 재구현하는 것입니다. 가변 인자(Variadic Arguments)를 다루는 stdarg.h 매크로의 동작 원리를 깊이 있게 이해하고, 다양한 데이터 타입(문자, 문자열, 정수, 주소값 등)을 지정된 서식에 맞춰 문자열로 변환하여 출력하는 '포맷팅 엔진'을 구축하는 것이 핵심입니다.

### 상세 라이브러리 설명
본 라이브러리는 다음과 같은 기능을 포함합니다:
- **라이브러리 구성요소**: 

ft_printf.c: 전체 흐름을 제어

ft_print_chars.c: 문자열과 문자 등 기초 데이터를 처리

ft_print_nums.c: 10진수와 부호 없는 정수를 처리

ft_print_hex.c: 16진수와 메모리 주소를 처리

### 알고리즘 및 데이터 구조
1. 가변 인자 처리 구조
ft_printf 함수는 va_list를 통해 인자들을 순차적으로 읽어들입니다. % 기호를 트리거로 삼아 뒤따르는 서식 지정자를 식별하며, 각 지정자에 대응하는 전용 출력 함수로 인자를 분기시키는 관제탑(Dispatching) 구조를 사용했습니다.

2. 재귀(Recursion) 기반 숫자 출력
정수(%d, %i, %u) 및 16진수(%x, %X) 출력 시 malloc 없이 재귀 함수를 활용했습니다.

근거: 숫자를 기수로 나눈 몫을 재귀적으로 넘겨 스택에 쌓고, 함수가 반환되는 시점에 나머지(1의 자리)를 출력함으로써 숫자를 정방향으로 출력합니다. 이는 추가적인 메모리 할당 없이 스택 공간만을 활용해 메모리 누수를 방지하고 코드를 간결하게 유지해줍니다.

3. Base Mapping 전략 (16진수 및 주소)
16진수 변환 시 "0123456789abcdef"라는 문자열 배열의 인덱스를 직접 참조하는 방식을 선택했습니다.

근거: 아스키코드를 연산으로 계산하는 방식보다 직관적이며, 대소문자 전환이 유연하고(문자열 교체만으로 가능), 향후 다른 진법으로의 확장성이 매우 뛰어납니다.

## 기술적 선택 사항 (Technical Rationale)
### 메모리 할당 전략  :  왜 malloc 대신 재귀(Recursion)인가?

일반적으로 숫자를 문자열로 바꿀 때 ft_itoa처럼 malloc으로 메모리를 할당하는 방식을 쓰지만, 본 프로젝트에서는 재귀 호출 방식을 채택했습니다.

메모리 안전성 (Memory Safety): malloc을 사용하면 출력 후 반드시 free를 해줘야 합니다. 하지만 출력 함수 내부에서 수시로 할당과 해제를 반복하면 메모리 누수(Memory Leak)의 위험이 커집니다. 재귀를 쓰면 힙(Heap) 메모리를 전혀 쓰지 않으므로 누수 걱정이 아예 없습니다.

구조적 간결함: itoa 방식은 숫자를 문자열로 바꾼 뒤 뒤집는(reverse) 과정이 필요하지만, 재귀는 함수가 리턴되면서 출력되는 스택(Stack)의 특성을 이용해 숫자 순서를 자동으로 맞춰줍니다.

효율성: 아주 큰 숫자를 출력할 때도 시스템의 스택 메모리 내에서 해결되므로 속도가 빠르고 코드가 훨씬 직관적입니다.
